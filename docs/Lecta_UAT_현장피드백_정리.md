# 1부. 화면별 피드백

## 1. 공통 (헤더, 내비게이션, 전체 스타일)

**헤더와 내비게이션**
- 헤더의 검정 버튼 자리는 지금 "Curate"인데, 이 자리를 로그인과 회원가입(Sign in, Sign up)으로 바꾸고 Curate는 메뉴 안쪽으로 넣기. (로그인 회원가입 큐레이트 자리에 / 큐레이트를 안쪽으로 넣고 검정색 버튼은 sign in sign up)
- 메뉴 이름만 보고는 기능을 알기 어려움. Discover가 추천인지, My exhibitions를 누르면 전시회를 보여주는 것인지 헷갈림. 섹터 이름과 기능이 더 분명히 맞아야 함. (디스커버 추천인가? 마이 전시하면 전시회를 보여주는건가?? 좀 더 섹터 이름과 기능이)
- 탭 이름에 한국어와 영어 전환 기능. (한/영 전환 - 탭 이름)
- 로고를 좀 더 두껍게. (로고 좀 더 두껍게)

**글꼴과 언어**
- 명조(세리프)와 고딕이 섞여 있어 통일감이 부족함. 서체 체계를 통일. (궁서체 고딕을 통일성)
- 태그가 한국어와 영어로 섞여 있음. 한 언어로 맞추거나 한영 전환과 연동. (한국어 영어 태그 다)
- 화면 이름이나 용어 표기 전반 점검. (이름들)

**스크롤과 탐색**
- 가로 스크롤인 곳은 옆으로 넘길 수 있다는 힌트를 더 분명하게. (가로 스크롤이라면 힌트가 좀 더 있게)
- 마우스 사용자는 휠로 스크롤하는 것이 편함. 휠만으로 화면 전체를 자연스럽게 오갈 수 있어야 함. (마우스는 스크롤이 편할 듯)
- 지금은 마우스가 가로 스크롤 영역 위에 있으면 휠을 굴려도 페이지가 아래로 내려가지 않아서, 커서를 영역 밖으로 옮겨야 밑으로 넘어감. 스크롤을 영역 기준으로 처리하지 말고, 휠의 방향을 보고 처리하는 함수로 바꾸기. 위아래로 굴리면 페이지가 위아래로 움직이고, 좌우 입력(트랙패드 옆으로 쓸기, Shift와 휠)일 때만 가로 영역이 움직이게. (스크롤링 region 기반이 아니라 그냥 함수로??)

## 2. 홈 `/`

- 첫 화면의 글씨 크기와 폭이 커서 작품이 잘 안 보임. 첫 화면에서 작품이 먼저 보이도록 글씨 비율과 폭 조정. (글씨 비율 폭이 첫 화면에 작품 보이는 걸 잘 보이게)
- 전체적인 내용이 잘 안 보임. 핵심 내용을 위쪽으로 올리기. (전체적인 내용이 잘 안 보임 / 전체 내용을 위쪽에 놓고)
- 방(전시)마다 벽 색이 비슷하면 전시끼리 차이를 못 느낌. 컬러 차트가 콘셉트라면 컬러 차트 아카이빙처럼 전시마다 색이 확실히 달라야 함. (컬러 차트가 컨셉이면 차트 아카이빙 컬러처럼 컬러가 동일하면 전시 차이 못 느낄 듯)

## 3. Discover `/discover`

**검색과 필터**
- 검색어를 한 글자 칠 때마다 화면이 새로고침되는 것처럼 보임. (검색에서 한 글자 한 글자 칠 때마다 화면 새로고침되는 거)
  - 원인: 지금 검색은 입력 후 0.22초마다 결과를 다시 받고, 결과가 바뀔 때마다 작품 전체를 다시 거는 전환 애니메이션을 실행합니다. 한글은 자음과 모음을 입력할 때마다 값이 바뀌어서 더 자주 일어납니다. 한글 조합이 끝난 뒤에만 검색하고, 대기 시간을 늘리고, 입력 중에는 전환 애니메이션을 끄는 방향으로 고칠 수 있습니다.
- 검색 입력창과 장르(분위기) 필터를 시각적으로 구분할 필요. (검색 필드랑 장르 필드가 약간 구분해 줄 필요)
- 태그 정렬과 정리. 태그를 장르나 카테고리별로 묶어서 보여주기. (태그 자체 sort / 태그 정리하기 장르별로)
- 매체별로 다른 태그. 영화, 책, 앨범마다 맞는 태그를 따로. (매체별로 태그)
- 국내와 해외 구분 필터. (국내 해외)

**작품 카드**
- 담기를 더 쉽게. 지금은 + 를 눌러야 담기는데, 커버를 누르면 바로 담기고, + 나 다른 버튼을 눌러야 세부 설명으로 가게 바꾸기. (추가를 좀 더 쉽게 플러스보다 커버를 누르면 담기 플러스나 다른 거 해야 세부 설명)
- 장르(매체 표시)와 제목을 한 덩어리로 묶어서 표시. (장르와 제목을 묶고)
- 시리즈도 다른 작품처럼 포스터 비율을 맞추기. 지금은 시리즈 이미지가 가로형이거나 글자 표지라 규격이 다름. (시리즈도 포스터 규격 맞춰서)

**없는 작품**
- 카탈로그에 없는 작품은 어떻게 하나. (없는 작품은 어떻게??)
- 새로운 영화 같은 작품을 사용자가 직접 추가하는 기능. (새로운 영화 추가 기능)
- 없으면 신청하고, 작품이 등록되면 알림. (없으면 신청하고 올라가면 노티)

**음악**
- 앨범뿐 아니라 곡 단위로 추가. (곡 단위 추가)
- 앨범 안에서 곡을 골라 담기. (곡 셀렉션)

**순서와 배치**

**글쓰기**
- 문단 형태로 길게 쓰기에는 지금 입력 필드가 불편함. 긴 글 형태의 폼이 필요함. (문단 형태로 쓰면 필드가 불편할 듯 / 긴 글 형태의 폼을)
- 맞춤법 검사 도구. (맞춤법 검사 툴도)

## 6. 전시실 `/exhibitions/[id]`

- 전시 상세를 새 페이지 대신 모달로 띄우고, 바깥 여백을 누르면 닫히게. (전시 상세 페이지 새 페이지 말고 모달로 띄워서 여백 누르면 나가지게)
- 큐레이션 화면의 자유도를 높여 더 커스터마이징할 수 있게. 지금은 작품이 가로로만 놓임. (큐레이션 페이지 자유도 높여서 더 커스터마이징할 수 있게 지금은 가로로만 됨)
- 큐레이터 코멘트(한 줄 이유)는 작품 바로 밑에. (코멘트는 작품 밑에)
- 가로로 이어지는 벽은 스크롤 힌트가 필요하고, 벽 위에서 휠을 위아래로 굴려도 페이지가 막히지 않고 내려가야 함. (공통 항목 참고)
- 방마다 벽 색이 확실히 달라야 함. (홈 항목 참고)
- "비공개(Private draft)" 같은 상태 표시와 서버 정보 같은 문구가 어색하게 줄바꿈됨. (서버 정보 비공개 이런 건 줄 넘김)

## 7. 추천 패널 (전시실 아래)

- 점수 구성(맥락, 이유, 주제 등)을 이어진 막대 하나로 보여주지 말고, 항목별 세로 막대그래프로. (맥락 이유 UI 이어지지 않고 막대그래프 세로로)

# 2부. 기획 전반

## 서비스의 메인 포인트
- 이 서비스의 메인 포인트가 나를 표현하는 것인지, 나만의 큐레이션을 공유하는 것인지. (이 서비스의 메인 포인트가 나를 표현하는 것이지 아니면 나만의 큐레이션을 공유하는 데 포인트인지)
- 사용자에게 보이는 지점이 어디인지. 해석 확인 필요. (보이는 지점)

## 나를 표현하는 방식
- 나를 표현하는 방식은 다양한데, 지금은 하나의 형식으로 고정되어 있음. 템플릿 기반 사이트처럼 여러 형식을 고를 수 있어야 함. (나를 표현하는 방식이 다양하게 있는데 고정하는 / 템플릿 기반 사이트)

## 블로그와의 경쟁력
- 네이버 블로그에는 서로이웃이 있고, 글을 쓸 때 영화, 책, 음악 정보를 넣는 "글감 선택" 기능이 있음. 글감을 골라 바로 블로그 글로 이어짐. (블로그 서이 / 블로그 글감 선택 → 블로그)
- 블로그는 게시판(카테고리)도 고를 수 있음. (게시판을 선택할 수 있는데)
- 그래서 지금 형태 그 자체로는 블로그와 비교해 경쟁력이 없음. (이것 자체로 블로그와의 경쟁력이 없다)
- 공간으로서 경쟁력이 있는가. 취향에 관한 부분에서 무엇이 다른가. (공간으로서의 경쟁력이 있는가? 취향에 관한 부분)

## 제안받은 방향
- 나의 취향을 모아 주는 콘텐츠를 카드뉴스나 블로그 템플릿으로 만들어 주기. (나의 취향을 모아주는 콘텐츠 카드뉴스 블로그의 템플릿)
- 작품과 코멘트를 불러와 스토리 공유처럼 카드뉴스 한 장으로 만들어 SNS에 공유. (불러가서 스공처럼 콘텐츠 코멘트 카드뉴스 한장 SNS에 공유)
- 블로그를 만들되, 나의 취향에 맞는 섹터별 템플릿을 제공. (블로그 만들어서 나의 취향에 맞는 섹터에 맞는 템플릿)

## 콘텐츠 범위
- 곡 단위, 국내와 해외 구분, 매체별 태그, 없는 작품 처리는 데이터 확보 전략과 함께 정해야 함. 자세한 조사는 `docs/Lecta_피드백_리서치.md`.

### 11:19 참석자 2 (질문: 작품 데이터 확보)

발표 아주 잘 들었습니다. 사실 저도 이런 취향과 관련된 전시나 음악 같은 것들을 미리 아카이빙해서 나중에 보고 싶다는 니즈가 강했어서 공감이 갔던 것 같아요. 궁금했던 점은, 사용자 입장에서 일단 자신의 취향을 등록해야 하잖아요. 그럴 때 커버 이미지나 전시 이름, 공개된 날짜 같은 다양한 데이터들이 사전에 DB에 많이 쌓여 있어야 할 것 같은데, 매체가 상당히 넓잖아요. 전시도 있고 음악도 있고 책도 있고 영화도 있고요. 굉장히 많은 데이터가 미리 엄청 많이 갖춰져 있어야 사용자가 등록할 때 편할 것 같은데, 혹시 이런 방대한 데이터를 수집할 수 있는 특별한 방법이 있는지 궁금해요.
